# Aggregator

## Назначение

Сводит выходы worker‑агентов в единый артефакт `state.result`, разрешает конфликты и устраняет дубли.

## Ответственности

- Собрать `state.research`, `state.architecture`, `state.security`, `state.analytics` (и custom‑поля).
- Привести их к согласованной структуре итогового документа / объекта.
- Разрешить конфликты по стратегии (приоритет ролей / голосование / LLM judge).
- Подготовить `summary` для пользователя.
- Передать управление Validator‑у.

## Входы

- Все ключи `state.<area>` от Worker Agents.

## Выходы

- `state.result` — структурированный итог (например, markdown‑документ или JSON).
- `state.conflicts` — список нерешённых противоречий (если есть).

## Взаимодействие со state

Owner: `state.result`, `state.conflicts`. Только читает выходы агентов.

## Зависимости

- LLM (для merge через summarization).
- Шаблоны итогового артефакта (markdown / JSON).

## Конфигурация

| Параметр | Значение |
|----------|----------|
| `conflict_strategy` | `priority|vote|llm_judge` |
| `template` | `default-report.md.j2` |
| `summary_max_tokens` | 800 |

## Безопасность

- Не делает внешних вызовов.
- Применяет PII guard к финальному `result`.

## Наблюдаемость

- Метрики: `aggregations_total`, `conflicts_total`, `result_size_bytes`.
- Лог: список модулей, чьи выходы были учтены.

## Failure modes & повторы

| Ошибка | Поведение |
|--------|-----------|
| Отсутствует обязательный блок (например, `architecture`) | вернуть ошибку Reflector‑у. |
| Невалидный шаблон | использовать fallback‑шаблон. |
| Слишком большой объём | усечение с пометкой и сохранением полной версии в object storage. |

## Точки расширения

- Альтернативные стратегии разрешения конфликтов (Bayesian merging).
- Доменные шаблоны (юр. документ, тех. дизайн, бизнес‑кейс).
